# MediaHub AI 采集闭环设计

日期：2026-05-12

## 目标

MediaHub 本轮从轻量内容推荐 Demo 升级为“公开 API + 公开网页 + AI 结构化增强”的可跑通闭环。核心目标是：

- 所有内容必须来自公开 API 或公开网页采集结果。
- 完全移除本地假数据和示例内容兜底。
- AI 只负责结构化抽取、归一化、摘要、标签和推荐理由增强。
- 本轮不引入数据库、后台管理、任务队列或批处理调度。
- 前端必须能清楚展示成功、空状态、错误、限流与重试。

## 非目标

本轮不实现以下能力：

- 绕过登录、验证码、付费墙、反爬机制或 robots/ToS 限制。
- 本地模拟数据、假内容兜底或硬编码内容库。
- 播放、下载、媒体库扫描、字幕、BT、在线播放。
- 数据库持久化、采集队列、后台管理、定时任务。
- 复杂机器学习推荐。

## 外部借鉴取舍

参考同类媒体追踪和发现项目后，本轮只吸收轻量且适合 MediaHub 的能力：

- 多来源内容聚合：保留清晰的数据源边界和统一内容模型。
- 用户清单闭环：保留已看、收藏、个人中心、推荐理由。
- 发现流体验：强调搜索、分类、详情、推荐与错误反馈。
- 不引入重型媒体服务器能力：播放、下载、库扫描、请求审批等均不做。

## 后端设计

### 模块边界

- `SourceAdapter`：统一数据源接口，负责调用公开 API 或公开网页。
- `ContentNormalizer`：把不同来源映射为统一 `Content`。
- `AiEnrichmentService`：对公开网页文本或 API 字段做结构化增强。
- `ContentService`：聚合真实数据，拒绝生成假数据。
- `RecommendationService`：基于已看、收藏、标签、IP 名称、作者/演员生成推荐。
- `UserService`：维持现有轻量会话用户、已看和收藏能力。

### 数据来源

第一轮继续使用免密公开 API，并预留公开网页采集适配器：

- `TVMaze`：短剧/剧集类内容。
- `Open Library`：小说和图书类内容。
- `Jikan`：动漫内容。
- `PublicWeb`：只抓取公开、无需登录、允许访问的页面文本。

### AI 增强边界

AI 增强服务输入：

- 来源 URL。
- 页面标题。
- 公开页面正文片段。
- API 原始字段。

AI 增强服务输出：

- `title`
- `summary`
- `type`
- `tags`
- `actors`
- `author`
- `ipName`
- `status`
- `reason`

如果 AI 无法抽取有效结构，服务返回 `422 ai_extract_failed`，前端展示失败状态，不生成假内容。

### 错误语义

- `400 invalid_request`：请求参数非法。
- `404 not_found`：内容不存在。
- `429 upstream_rate_limited`：上游限流。
- `502 upstream_unavailable`：公开 API 或公开网页不可用。
- `422 ai_extract_failed`：AI 抽取失败。
- `500 internal_error`：未分类服务器错误。

### 缓存策略

本轮允许内存缓存真实 API/公开网页结果，以减少上游请求和限流风险。

约束：

- 缓存只能保存真实来源结果。
- 缓存未命中且上游失败时，必须返回错误。
- 不使用本地假数据填充 UI。

## 前端设计

### 首页

保留当前核心结构：

- 为你推荐。
- 热门内容。
- 分类 Tab。
- 搜索框。
- 热度/最新排序。
- 加载更多。

优化重点：

- API 失败时显示来源不可用、重试按钮和错误原因。
- 空列表显示明确空状态，不显示假卡片。
- 分类切换、搜索、排序时保持状态清晰。
- 移动端卡片信息减少拥挤，按钮更易点击。

### 详情页

详情页展示：

- 标题、封面、类型、状态、热度。
- 作者/演员、标签、摘要。
- 来源和更新时间。
- 标记已看、收藏。
- 同 IP / 相似推荐，若为空则隐藏。

### 个人中心

保留：

- 用户轻量登录。
- 观看历史。
- 收藏列表。
- 分类统计。

本轮不做完整账号体系。

## 数据流

列表页数据流：

1. 前端请求 `/api/contents`。
2. 后端按类型选择数据源适配器。
3. 适配器调用公开 API 或公开网页。
4. 归一化为 `Content`。
5. 写入真实结果内存缓存和快照。
6. 前端渲染列表、空状态或错误状态。

详情页数据流：

1. 前端请求 `/api/contents/:id`。
2. 后端解析来源 ID。
3. 调用对应公开数据源。
4. 可选调用 AI 增强摘要和标签。
5. 聚合同 IP / 相似内容。
6. 前端渲染详情和推荐区。

用户推荐数据流：

1. 用户标记已看或收藏。
2. 后端保存内容快照和用户行为。
3. 推荐服务根据用户行为提取标签、作者/演员、IP 名称。
4. 从真实内容池中排序并生成推荐理由。

## 测试策略

### 自动验证

- `npm run lint --workspace=frontend`
- `npm run build`
- 后端 API smoke：`/api/health`、`/api/categories`、四类 `/api/contents`、详情、推荐、用户接口。

### 浏览器验证

使用 Chrome 浏览器测试：

- 首页加载。
- 四个分类 Tab。
- 搜索。
- 排序。
- 加载更多。
- 卡片进入详情。
- 登录。
- 标记已看。
- 收藏/取消收藏。
- 个人中心历史和收藏。
- 移动端布局。
- 上游失败时错误状态和重试。

## 工程原则

- KISS：保留清晰的 API 聚合闭环，不引入数据库和队列。
- YAGNI：不做播放、下载、后台管理和完整账号体系。
- DRY：抽出统一来源适配、归一化和错误语义。
- SOLID：数据源适配、AI 增强、内容聚合、用户行为各自单一职责。

## 验收标准

- 项目不再展示任何“示例短剧A”等本地假数据。
- API 成功时展示真实公开来源内容。
- API 失败时前端显示明确错误和重试入口。
- 首页、详情页、个人中心主流程可在浏览器中跑通。
- lint 和 build 通过。
- 不需要本地数据库即可运行。
